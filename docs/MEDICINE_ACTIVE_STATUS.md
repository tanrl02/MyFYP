# Active and inactive medicines

Implemented19October2026. Staff stock cards show Active or Inactive. Choose Mark inactive or Reactivate, review the item and consequences, then confirm. Cancel makes no change. Inactive items stay in the staff catalogue with stock retained; receiving and name-price editing remain available. Inactive status controls future prescription choices. No deletion or automatic patient notification.

Doctors see only active items in new prescription forms. The server checks active status inside the issuance transaction, so a stale client cannot prescribe an inactive item. If polling removes an item with a positive quantity from an open doctor draft, submission shows a review error rather than silently omitting the item. Cancel/reopen resets quantities to current choices. A concurrent issuance/deactivation serializes: issuance committed first remains valid; deactivation committed first blocks new issuance.

Existing issued prescriptions retain snapshots and support exact content retries while inactive. Dispensing still uses the existing stock checks and allows inactive issued items. Receiving stock remains allowed; no automatic stock changes occur. Existing and subsequently generated bills use issued snapshots. Reactivation restores eligibility for future prescriptions on the same medicine ID.

API: staff-only POST /medicines/{id}/status accepts strict boolean active,version,request_id. Status and name-price editing share the same version counter; stale changes cannot overwrite newer ones. A serialized transaction updates only active/version/updated_at and records old/new status,actor/time,expected version and historical response in medicine_status_changes. Audit failure rolls back the change. Exact retries return the original response without changing newer status/stock. Reusing a key for different details conflicts; a same-status new request is rejected and asks for reload.

Migration adds medicines.active default1 with a0/1 constraint. All legacy items remain active without changing IDs,names,prices,stock or Rx/invoice snapshots. No original JSON/request records are rewritten. Old pre-status medicine-edit response snapshots receive additive historical active=true when replayed; they never reactivate current items. Original Add retries return current item/status and duplicate identities stay rejected even if inactive. GET /medicines returns all items to staff and active-only to doctors; staff /stock retains both statuses. Demo permissions otherwise unchanged.
