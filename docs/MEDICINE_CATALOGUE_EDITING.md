# Editing medicine catalogue names and prices

Implemented19October2026. Existing Add catalogue item remains available with zero starting stock and its existing review/confirmation. Staff now choose Edit name and price on an item in Pharmacy stock. The editor loads saved values/version, accepts name and unit price, and reviews before/after values before confirmation. Keep editing retains draft values; Cancel closes without saving; Reload latest item explicitly discards draft changes and loads current values after a conflict. Polling updates stock cards without overwriting the editor draft.

Name is required and limited to100 characters; price is integer cents from0 to1,000,000 (RM0.00–10,000.00), displayed with up to two decimals. Duplicate name/strength/form matches are rejected using the existing case-insensitive catalogue policy. Strength and dosage form remain fixed. Receiving/dispensing continue to control stock; editing never writes stock. Deletion, identity-strength/form changes, expiry and deactivation are outside this increment.

Doctor prescribing forms see the current catalogue after their existing refresh. Prescriptions snapshot name, strength/form and price at issuance; editing the catalogue cannot change issued snapshots. Bills generated later from those prescriptions still use issued prices, and already-created unpaid/paid invoices remain immutable. Later prescriptions snapshot the edited catalogue values. Patient clinical access is unchanged.

API/storage: staff-only POST /medicines/{medicine_id}/edit requires name,price_cents,version,request_id. Extra fields such as stock/strength/form are rejected. A serialized transaction checks identity/version/duplicates and updates only name,price,version,timestamp, then inserts an immutable medicine_edits audit/request row with original/current values, actor/time and response. Failure rolls the whole edit back. Exact retries return their saved historical response even after later edits, without reverting current state. The UI refreshes current stock/catalogue after saving. A new stale request is rejected and requires reload.

Additive medicine columns: version(default0),updated_at(nullable),creation_json(original creation payload). Existing rows are backfilled without changing IDs, stock, prices or source request IDs; prescription/bill snapshots stay intact. Original creation requests compare their immutable creation payload and return the current catalogue item, preserving retry safety after edits. Internal creation/request payloads are omitted from operational catalogue and staff stock responses. No dependency or permission expansion; demo auth remains unchanged.
